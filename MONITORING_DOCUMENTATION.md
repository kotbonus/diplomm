# Система мониторинга и сбора логов приложения Wishlist

## Обзор

В рамках дипломной работы реализована полнофункциональная система мониторинга и сбора логов, обеспечивающая полное наблюдение за работой приложения в продакшн-среде. Система построена на основе современных open-source инструментов и следует лучшим практикам DevOps.

## Архитектура системы мониторинга

### Компоненты

1. **Prometheus** - система сбора временных рядов (метрик)
2. **Grafana** - платформа визуализации и дашбордов
3. **Loki** - система агрегации логов
4. **Promtail** - агент сбора логов
5. **Spring Boot Actuator** - экспорт метрик приложения
6. **Micrometer** - библиотека для работы с метриками

### Схема взаимодействия

```
Приложение Spring Boot
├── Actuator (/actuator/prometheus) → Prometheus
├── Logback → Loki (через Promtail)
└── Micrometer → Custom Metrics → Prometheus

Prometheus → Grafana (визуализация)
Loki → Grafana (анализ логов)
```

## Настройка метрик

### Бизнес-метрики приложения

#### Метрики пользователей
- `user_registrations_total` - количество регистраций пользователей
- `user_logins_total` - количество успешных входов
- `users_active` - количество активных пользователей
- `security_auth_failures_total` - количество неудачных попыток аутентификации

#### Метрики функциональности
- `wishlist_items_created_total` - количество созданных желаний
- `wishlist_items_updated_total` - количество обновленных желаний
- `friendship_requests_total` - количество запросов в друзья
- `password_reset_requests_total` - количество запросов на сброс пароля

#### Метрики парсинга цен
- `price_parsing_attempts_total` - количество попыток парсинга
- `price_parsing_success_total` - количество успешных парсингов
- `price_parsing_errors_total` - количество ошибок парсинга
- `price_parsing_duration_seconds` - время выполнения парсинга

#### Системные метрики
- `http_requests_total` - общее количество HTTP запросов
- `http_requests_error_total` - количество HTTP ошибок
- `jvm_memory_used_bytes` - использование памяти JVM
- `process_cpu_seconds_total` - использование CPU

### Технические метрики

#### Производительность
- Таймеры для измерения времени выполнения методов
- Гистограммы для анализа распределения времени ответа
- Счетчики для отслеживания количества операций

#### Доступность
- Health checks для проверки состояния системы
- Метрики uptime и доступности сервисов
- Индикаторы работоспособности внешних зависимостей

## Система логирования

### Уровни логирования

1. **ERROR** - критические ошибки, требующие немедленного внимания
2. **WARN** - предупреждения о потенциальных проблемах
3. **INFO** - информационные сообщения о бизнес-операциях
4. **DEBUG** - отладочная информация для разработки

### Типы логов

#### Application Logs
- Основные логи работы приложения
- Файл: `logs/application.log`
- Ротация: 10MB, 30 дней хранения

#### Error Logs
- Только ошибки уровня ERROR
- Файл: `logs/error.log`
- Отдельный файл для быстрого поиска проблем

#### Audit Logs
- Аудит безопасности и важных операций
- Файл: `logs/audit.log`
- События: регистрация, вход, сброс пароля

#### Performance Logs
- Метрики производительности
- Файл: `logs/performance.log`
- Время выполнения критических операций

### Защита конфиденциальных данных

#### Маскирование PII (Personally Identifiable Information)
```java
// Маскирование email
ivan.ivanov@example.com → iv***@example.com

// Маскирование URL
https://example.com/product/12345 → https://example.com/***
```

#### Правила маскирования
- Email: показываются первые 2 символа до @
- URL: показывается только домен
- Пароли и токены: полностью исключаются из логов
- Персональные данные: заменяются на маски

### Основные дашборды

#### 1. Wishlist App - Обзор системы
- **Активные пользователи** - текущее количество активных сессий

- **Процент ошибок HTTP** - качество работы API

#### 2. Wishlist App - Безопасность
- **Неудачные аутентификации** - мониторинг атак
- **События безопасности** - общие события
- **Запросы на сброс пароля** - аномальная активность
- **Соотношение успешных/неудачных входов** - качество аутентификации

#### 3. System Logs - Анализ логов
- Поиск по логам через Loki
- Фильтрация по уровням логирования
- Анализ ошибок и предупреждений
- Корреляция событий с метриками

## Система алертов

### Правила алертов

#### Критические (Critical)
- **Application Down** - приложение недоступно
- **Critical Authentication Failures** - >50 неудачных входов за 5 минут
- **Critical HTTP Errors** - >30% HTTP ошибок

#### Предупреждения (Warning)
- **High Authentication Failures** - >10 неудачных входов за 5 минут
- **High Parsing Errors** - >50% ошибок парсинга цен
- **Slow Parsing** - 95-й перцентиль > 5 секунд
- **High HTTP Errors** - >10% HTTP ошибок
- **High CPU Usage** - загрузка CPU > 80%
- **High Memory Usage** - использование памяти > 85%

#### Информационные (Info)
- **Low User Activity** - отсутствие входов за час
- **High Password Reset Requests** - >20 запросов на сброс пароля

### Каналы уведомлений
- Email для critical алертов
- Slack для warning алертов
- Dashboard для info алертов

## Развертывание системы мониторинга

### Запуск через Docker Compose

```bash
# Запуск стека мониторинга
docker-compose -f docker-compose-monitoring.yml up -d

# Проверка статуса
docker-compose -f docker-compose-monitoring.yml ps
```

### Доступ к компонентам

- **Grafana**: http://localhost:3000 (admin/admin123)
- **Prometheus**: http://localhost:9090
- **Loki**: http://localhost:3100
- **Promtail**: http://localhost:9080

### Настройка приложения

```properties
# Включение Actuator
management.endpoints.web.exposure.include=health,info,metrics,prometheus
management.endpoint.health.show-details=always

# Настройка метрик
management.metrics.export.prometheus.enabled=true
management.metrics.tags.application=wishlist-app
```

## Анализ производительности

### Ключевые показатели (KPI)

#### Производительность парсинга
- **Целевой процент успешности**: >95%
- **Целевое время ответа**: <2 секунд (95-й перцентиль)
- **Допустимая задержка**: <5 секунд (95-й перцентиль)

#### Веб-производительность
- **Целевой RPS**: 10 запросов в секунду
- **Процент ошибок**: <1%
- **Время ответа**: <500мс (95-й перцентиль)

#### Безопасность
- **Уровень неудачных аутентификаций**: <5% от общего числа
- **Порог срабатывания алертов**: >10 за 5 минут

### Мониторинг в реальном времени

#### Метрики для наблюдения
1. **Нагрузка на систему** - RPS, активные пользователи
2. **Производительность** - время ответа, успешность операций
3. **Ресурсы** - CPU, память, диск
4. **Бизнес-показатели** - регистрации, парсинг цен

#### Процедура инцидентов
1. **Обнаружение** - автоматические алерты
2. **Анализ** - проверка дашбордов и логов
3. **Диагностика** - корреляция метрик и логов
4. **Устранение** - применение исправлений
5. **Пост-анализ** - анализ причин и улучшение

## Заключение

Реализованная система мониторинга обеспечивает полное наблюдение за работой приложения, позволяя:

1. **Проактивно выявлять проблемы** до их влияния на пользователей
2. **Анализировать производительность** и оптимизировать систему
3. **Обеспечивать безопасность** через мониторинг подозрительной активности
4. **Принимать решения** на основе данных и метрик
5. **Соответствовать требованиям** к продакшн-эксплуатации

Система готова к использованию в продакшн-среде и может быть легко расширена для мониторинга дополнительных компонентов приложения.
