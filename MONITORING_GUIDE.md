# Руководство по мониторингу Wishlist App

## Обзор системы мониторинга

Система мониторинга построена на стеке:
- **Prometheus** - сбор метрик
- **Grafana** - визуализация и дашборды
- **Loki** - агрегация логов
- **Promtail** - отправка логов в Loki
- **Spring Boot Actuator** - экспорт метрик приложения

## Запуск системы мониторинга

### 1. Запуск контейнеров мониторинга

```bash
# Запустить все сервисы мониторинга
docker-compose -f docker-compose-monitoring.yml up -d

# Проверить статус
docker-compose -f docker-compose-monitoring.yml ps
```

### 2. Запуск приложения

```bash
# Запустить Spring Boot приложение
mvn spring-boot:run

# Или собрать и запустить
mvn clean package
java -jar target/diplomm-1.0-SNAPSHOT.jar
```

## Доступ к интерфейсам

- **Grafana**: http://localhost:3000 (admin/admin123)
- **Prometheus**: http://localhost:9090
- **Loki**: http://localhost:3100
- **Приложение**: http://localhost:8080
- **Метрики приложения**: http://localhost:8081/actuator/prometheus

## Собираемые метрики

### Бизнес-метрики
- `user_registrations_total` - количество регистраций пользователей
- `user_logins_total` - количество входов пользователей
- `wishlist_items_created_total` - количество созданных желаний
- `wishlist_items_updated_total` - количество обновленных желаний
- `price_parsing_attempts_total` - попытки парсинга цен
- `price_parsing_success_total` - успешные парсинги цен
- `price_parsing_errors_total` - ошибки парсинга цен
- `friendship_requests_total` - запросы в друзья
- `password_reset_requests_total` - запросы сброса пароля

### Метрики производительности
- `price_parsing_duration_seconds` - время парсинга цен
- `database_query_duration_seconds` - время запросов к БД
- `http_request_duration_seconds` - время HTTP запросов

### Системные метрики
- `users_active` - количество активных пользователей
- `wishlist_items_total` - общее количество желаний
- `price_parsing_queue_size` - размер очереди парсинга

### Метрики безопасности
- `security_auth_failures_total` - неудачные аутентификации
- `security_events_total` - события безопасности

## Дашборды Grafana

### 1. Wishlist App - Обзор системы
- Активные пользователи
- Регистрации и входы
- HTTP запросы (RPS и время ответа)
- Статистика парсинга цен
- Ошибки аутентификации

### 2. Wishlist App - Логи и Безопасность
- Ошибки приложения в реальном времени
- Аудит событий
- Производительность операций
- Графики ошибок и событий безопасности

## Алерты

### Критические алерты
- **ApplicationDown** - приложение недоступно
- **NodeDown** - сервер недоступен
- **HighDiskUsage** - мало места на диске (<10%)

### Предупреждающие алерты
- **HighErrorRate** - высокий уровень HTTP 5xx ошибок (>10%)
- **HighResponseTime** - высокое время ответа (>2с)
- **PriceParsingHighErrorRate** - высокий уровень ошибок парсинга (>50%)
- **HighAuthenticationFailures** - много неудачных входов (>5/мин)
- **HighMemoryUsage** - высокое использование памяти (>512MB)
- **HighCPUUsage** - высокая загрузка CPU (>80%)

## Логирование

### Уровни логов
- **application.log** - общие логи приложения
- **error.log** - только ошибки
- **audit.log** - аудит действий пользователей
- **performance.log** - метрики производительности

### Структурированные логи
Каждый лог содержит:
- Временную метку
- Уровень логирования
- Имя логгера
- MDC контекст (email пользователя, операция)
- Сообщение

### Примеры логов

#### Аудит действий
```
2024-01-15 10:30:45.123 INFO  AUDIT - USER_LOGIN | email: user@example.com | ip: 192.168.1.100 | success: true
2024-01-15 10:31:02.456 INFO  AUDIT - WISHLIST_ITEM_CREATE | user_id: 123 | item_name: "Новый телефон" | price: 29990
```

#### Производительность
```
2024-01-15 10:32:15.789 INFO  PERFORMANCE - PRICE_PARSE_SUCCESS | url: https://example.com/product/123 | price: 29990 | duration: 1250ms
2024-01-15 10:32:16.012 INFO  PERFORMANCE - DB_QUERY | table: wishlist_items | operation: SELECT | duration: 45ms
```

## Безопасность мониторинга

### Защита данных
- Маскирование email в логах (`us***@example.com`)
- Отсутствие паролей и токенов в логах
- Фильтрация чувствительных параметров запросов

### Контроль доступа
- Grafana требует аутентификацию
- Prometheus доступен только из внутренней сети
- Логи хранятся с ротацией (10MB, 30 дней, 1GB всего)

### Аудит безопасности
- Логирование всех попыток входа
- Отслеживание неудачных аутентификаций
- Мониторинг подозрительной активности

## Анализ данных

### Ключевые показатели производительности
1. **RPS (Requests Per Second)** - нагрузка на систему
2. **Время ответа** - скорость обработки запросов
3. **Успешность парсинга** - надежность внешних сервисов
4. **Активность пользователей** - вовлеченность

## Расширение системы

### Добавление новых метрик
1. Определить метрику в `MetricsConfig`
2. Добавить счетчик/таймер в сервис
3. Обновить дашборд Grafana

### Настройка алертов
1. Добавить правило в `wishlist-alerts.yml`
2. Перезапустить Prometheus
3. Настроить каналы уведомлений

### Интеграция с другими системами
- Slack/Telegram для уведомлений
- PagerDuty для дежурных
- ELK Stack для расширенного анализа логов

## Технические требования

### Ресурсы для мониторинга
- CPU: 2 cores
- RAM: 4GB
- Disk: 20GB (для логов и метрик)

### Сетевые порты
- 3000 - Grafana
- 9090 - Prometheus
- 3100 - Loki
- 8080 - Приложение
- 8081 - Actuator

### Резервное копирование
- Конфигурации Grafana
- Правила алертов Prometheus
- Настройки дашбордов
