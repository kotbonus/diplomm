# Тестирование системы мониторинга

## Пошаговая инструкция для проверки

### 1. Запуск системы

```bash
# 1. Запустить мониторинг
docker-compose -f docker-compose-monitoring.yml up -d

# 2. Проверить статус контейнеров
docker-compose -f docker-compose-monitoring.yml ps

# 3. Запустить приложение
mvn spring-boot:run
```

### 2. Проверка доступности сервисов

Откройте в браузере:

- **Grafana**: http://localhost:3000 (admin/admin123)
- **Prometheus**: http://localhost:9090
- **Приложение**: http://localhost:8080
- **Метрики**: http://localhost:8081/actuator/prometheus

### 3. Проверка метрик в Prometheus

В интерфейсе Prometheus выполните запросы:

```promql
# Проверка доступности приложения
up{job="wishlist-app"}

# Проверка HTTP запросов
rate(http_server_requests_seconds_count[5m])

# Проверка бизнес-метрик
rate(user_registrations_total[5m])
rate(price_parsing_attempts_total[5m])
```

### 4. Проверка дашбордов Grafana

1. Войдите в Grafana (admin/admin123)
2. Перейдите в Dashboards → "Wishlist App - Обзор системы"
3. Проверьте отображение метрик:
   - Активные пользователи
   - Регистрации и входы
   - HTTP запросы
   - Статистика парсинга цен

### 5. Тестирование алертов

Создайте нагрузку для проверки алертов:

```bash
# Создание нагрузки (в другом терминале)
for i in {1..100}; do curl http://localhost:8080/; done

# Проверка алертов в Prometheus
# http://localhost:9090/alerts
```

### 6. Проверка логов

1. Проверьте файлы логов:
   ```bash
   ls -la ./logs/
   tail -f ./logs/application.log
   ```

2. Проверьте логи в Grafana:
   - Перейдите в Dashboards → "Wishlist App - Логи и Безопасность"
   - Проверьте отображение ошибок и аудита

### 7. Тестирование бизнес-метрик

Выполните действия в приложении:

1. **Регистрация пользователя**:
   - Откройте http://localhost:8080/auth/register
   - Зарегистрируйте нового пользователя
   - Проверьте метрику `user_registrations_total`

2. **Вход в систему**:
   - Войдите под созданным пользователем
   - Проверьте метрику `user_logins_total`

3. **Парсинг цен**:
   - Добавьте желание с URL товара
   - Проверьте метрики `price_parsing_attempts_total` и `price_parsing_success_total`

### 8. Проверка производительности

В Prometheus выполните:

```promql
# Время ответа 95th percentile
histogram_quantile(0.95, rate(http_server_requests_seconds_bucket[5m]))

# Среднее время парсинга цен
rate(price_parsing_duration_seconds_sum[5m]) / rate(price_parsing_duration_seconds_count[5m])

# Использование памяти
process_resident_memory_bytes / 1024 / 1024
```

### 9. Проверка безопасности

1. Попробуйте войти с неверным паролем несколько раз
2. Проверьте метрику `security_auth_failures_total`
3. Проверьте логи аудита в Grafana

### 10. Ожидаемые результаты

#### Успешные метрики
- `up{job="wishlist-app"}` = 1 (приложение доступно)
- `http_server_requests_seconds_count` > 0 (есть запросы)
- Логи появляются в Grafana
- Алерты срабатывают при превышении порогов

#### Типичные проблемы и решения

**Проблема**: Приложение не доступно в Prometheus
**Решение**: Проверьте, что приложение запущено на порту 8081

**Проблема**: Нет логов в Grafana
**Решение**: Проверьте конфигурацию Promtail и пути к файлам логов

**Проблема**: Алерты не работают
**Решение**: Проверьте правила алертов в prometheus.yml

### 11. Очистка

```bash
# Остановка всех сервисов
docker-compose -f docker-compose-monitoring.yml down

# Удаление данных (при необходимости)
docker-compose -f docker-compose-monitoring.yml down -v
```
